## Objective

The goal of this audit is to evaluate your ability to **analyze, test, and reason about a software
system** from a quality and testing perspective. You are expected to demonstrate both
conceptual understanding and practical experience in software testing — manual testing,
automated testing, and continuous integration (CI).
Your presentation must be structured around the following themes in a cohesive order that
resonates with your project and storytelling.

1. Project overview and collaboration
    - Briefly describe the project
    - Explain how you collaborated as a team:
         - Which communication channels you used (e.g. Discord, GitHub, meetings, etc.)
         - Advantages and disadvantages of those channels
    - Reflect on how communication affected development and testing.
2. Requirements and documentation
    - Describe the **functional requirements** of the project.
    - Explain how these requirements were documented:


```
  - Structure of documentation
  - How documentation supports development and testing
  - Describe how you ensured that the implemented functionality matched the requirements.
```
3. Code review and quality control
    - Explain how code reviews were handled:
         - Who performed them?
         - Why were these the best practices?
    - Describe how code reviews contributed to quality and reduced defects. Give practical examples.
    - Explain the test files used for unit testing
4. Testing strategy and test planning
    - Describe how test plans were designed.
    - Clarify:
         - Which parts of the test planning you actively worked on
         - How test cases were identified and prioritized
5. Test environments
    - Describe all test environments you used, including a Continuous Integration (CI) environment.
    - Explain:
         - Which environments were easiest to set up and why
         - How the CI environment was configured
6. Manual vs automated testing
    - **Manual testing**
         - When and why it was preferred
         - How manual tests were documented
    - **Automated testing***
         - When and why automated tests were preferred.
         - How automated tests were documented
         - Tools used
         - When tests were executed (e.g. CI, pre-merge, nightly)
         - Which tests are executed automatically in CI
       * **If the project already includes automated tests, these can be used in the presentation. If not, students are expected to add automated tests and present them during the audit.**
7. Reporting and results
    - Explain how test results were reported:
         - Who received them?
         - Through which channels?
    - Reflect on how test results influenced decisions or changes in the project.

## Evaluation Criteria


## Software Testing

**The student analyzes and evaluates a data system.**
- What different channels do you use to communicate with your team members?
- What are the advantages and disadvantages of the different channels you use?
- Based on a software project you have participated in, answer the following questions:
  - Describe the project.
  - What are the functional requirements for different parts of the project?
  - How is the documentation structured to reflect these requirements?
  - How do/did you ensure that the desired functionality was actually fulfilled?
  - Who performs code reviews? On what basis was this person/these people selected?
  - Describe the process of designing test plans. Which parts did you actively participate in?

**The student tests a data system using test automation tools.**
- Describe the test environments you use.
- Which environments are the easiest to set up?
- When are manual testing methods preferred? How do you document them?
- When are automated tests preferred? How are they documented? When are they executed?
- Who do you report your test results to? How?
